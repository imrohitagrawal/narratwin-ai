# ADR 0086: Manifest scope for work-record documentation

Status: proposed in Issue559; effective only after reviewed merge.

## Context

The frozen Phase1 path list predates stable docs/work records and rejects the
separate personal-avatar pilot preparation. Per-issue central allowlists would
repeat the configurable-governance defect. Existing GovernancePreflightV1 already
owns branch/issue/firstcommit/exact scope and change-budget data.

## Decision

A small scope adapter consumes that contract for prospective work-record docs.
Independent documentation envelope prevents arbitrary manifest-declared runtime
privilege; actual committed/current content and budgets are verified. Replace
only the frozen scope list choice and preserve every semantic/parity check.
Install the complete stable adapter/wrapper/test kernel only when absent at base;
installed bases cannot alter it through documentation manifests. Other legacy
and specialized routes keep their existing behavior.

## Consequences

Work records can evolve as reviewed data without adding per-issue implementation
literals. Local pending work is not hosted acceptance; history, clean checkout,
source identity and exact-head CI remain separate gates. No product/provider
capability or permission is created. Kernel maintenance requires another route.
No frozen files, protection settings, runtime dependencies or media change.
